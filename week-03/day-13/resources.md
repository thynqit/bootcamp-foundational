# Resources – Day 13: Authentication & Authorization

> Part of the Thynqit Labs – Foundational Engineering Bootcamp

---

## 📌 Overview

These resources help you understand how modern systems secure users, data, and APIs.

They cover:

- authentication and authorization fundamentals
- token-based security (JWT)
- OAuth and SSO mechanisms
- enterprise identity systems
- real-world API security practices

Understanding these concepts is essential for building secure backend systems.

---

## 📖 Official Documentation & Authoritative Sources

These are widely trusted, industry-standard references.

---

### Auth0 – Authentication vs Authorization

https://auth0.com/docs/get-started/identity-fundamentals/authentication-and-authorization

Explains:

- difference between authentication and authorization
- real-world examples
- identity and access concepts

---

### OAuth 2.0 (Official Specification – RFC 6749)

https://datatracker.ietf.org/doc/html/rfc6749

Covers:

- OAuth flows
- authorization grants
- access tokens
- client-server interactions

This is the official standard for OAuth.

---

### JWT (JSON Web Token)

https://jwt.io/introduction

Explains:

- structure of JWT (header, payload, signature)
- how tokens are generated and verified
- how JWT is used in APIs

---

### Okta – What is Authentication?

https://www.okta.com/identity-101/authentication/

Covers:

- authentication methods
- identity verification
- enterprise authentication systems

---

### Okta – What is Authorization?

https://www.okta.com/identity-101/authorization/

Explains:

- access control
- permissions and roles
- authorization strategies

## 📌 Suggested Learning Flow

1. Start with Auth0 explanation of authentication vs authorization.
2. Understand JWT structure using jwt.io.
3. Learn OAuth flows from Auth0 or RFC documentation.
4. Explore Okta and Microsoft identity systems.
5. Study AWS IAM for real-world authorization systems.
6. Watch videos to visualize flows and concepts.

> Security is not optional in modern systems — it is a core engineering responsibility.
