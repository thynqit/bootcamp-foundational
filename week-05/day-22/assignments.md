# Assignments – Day 22: Product Requirement Document (PRD)

> Part of the Thynqit Labs – Foundational Engineering Bootcamp

---

# 📌 Overview

In this assignment, learners will think like:

- product managers
- engineering teams
- UX designers
- solution architects

to transform business requirements into structured product requirements.

The goal is to understand how:

```plaintext
Business Goals
    ↓
Product Features
    ↓
User Journeys
    ↓
Engineering Planning
```

connect together before implementation begins.

This assignment continues the same platform selected during Day 21 BRD exercises.

---

# 🎯 Assignment Objectives

By completing this assignment, learners should be able to:

- convert business requirements into product requirements
- define product features clearly
- identify user personas and workflows
- define product scope
- document user journeys
- identify product-level functional and non-functional requirements
- connect product requirements with future engineering design

- 2 detailed user journeys

# 📄 Part 4 – Create a PRD

Using:

```plaintext
templates/product-requirements/prd-markdown.md
templates/product-requirements/prd-document.docx
templates/product-requirements/prd-document.pdf
```

create a Product Requirement Document for your selected platform.

Your PRD should include:

- Product Overview
- Product Goals
- User Personas
- Product Features
- User Journeys
- Functional Requirements
- Non-Functional Requirements
- Dependencies
- Risks
- Success Metrics

---

# ⚙️ Part 5 – Functional vs Non-Functional Requirements

Document at least:

- 7 Functional Requirements
- 5 Non-Functional Requirements

---

## Example Functional Requirement

```plaintext
Users should be able to track delivery status in real time.
```

---

## Example Non-Functional Requirement

```plaintext
The platform should support 100,000 concurrent users during peak hours.
```

# 🧠 Part 6 – Product Thinking Reflection

Answer the following questions.

---

## Reflection Questions

1. Which product workflow is most critical to user experience?

2. Which product feature may create scalability challenges?

3. Which user journey may require the most APIs?

4. Which product feature may heavily influence database design?

5. Which product feature may require stronger security mechanisms?

6. Which non-functional requirement may significantly impact infrastructure costs?

7. Which product risk may require monitoring and observability systems?

# 🧠 Engineering Insight

Strong engineering systems are built on strong product understanding.

Product requirements directly influence:

- API design
- database schemas
- caching strategies
- infrastructure planning
- scalability architecture

The quality of future system design often depends on the clarity of product requirements.
