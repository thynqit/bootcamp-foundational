## 📌 Overview

These resources help you understand how APIs work in modern software systems.

They cover:

- API fundamentals
- REST architecture
- API design best practices
- tools used for testing and exploring APIs
- documentation systems such as Swagger / OpenAPI

Learning how APIs work is essential for backend engineers, frontend developers, mobile developers, and QA engineers.

## 🛠 API Tools for Developers

These tools allow engineers to test and explore APIs.

---

### Postman

https://www.postman.com/

Postman allows developers to:

- send HTTP requests
- inspect responses
- test APIs
- manage API collections

Postman is one of the most widely used API testing tools.

---

### Bruno (Git-Friendly API Client)

https://www.usebruno.com/

Bruno is an open-source API client designed for developers.

Key advantages:

- API collections stored as **plain text files**
- easy to **version control using Git**
- lightweight and developer-friendly
- works well with CLI-based workflows

Bruno is increasingly used by engineering teams that prefer API testing tools integrated with Git-based development.

---

### Swagger UI

https://swagger.io/tools/swagger-ui/

Swagger UI allows developers to:

- visualize API documentation
- test API endpoints directly from a browser
- explore request and response models

Many production APIs provide Swagger documentation.

---

### Hoppscotch (Lightweight API Client)

https://hoppscotch.io/

A browser-based tool that allows you to:

- send HTTP requests
- inspect responses
- test APIs quickly

It is a lightweight alternative to Postman.

---

## 🌐 Public APIs for Practice

These APIs allow you to explore real API responses.

---

### Fake Store API (E-commerce Mock API)

https://fakestoreapi.com/

A mock e-commerce API that returns realistic product and cart data.

Example endpoints:

```
https://fakestoreapi.com/products
https://fakestoreapi.com/products/1
https://fakestoreapi.com/users
https://fakestoreapi.com/carts
```

You can use this API to practice:

- fetching product catalogs
- retrieving single resources
- inspecting JSON responses
- testing APIs using Postman, Bruno, or curl

---

### JSONPlaceholder (Mock API)

https://jsonplaceholder.typicode.com/

Example endpoints:

```
https://jsonplaceholder.typicode.com/users
https://jsonplaceholder.typicode.com/posts
```

Useful for learning:

- API responses
- JSON structures
- HTTP methods

---

### ReqRes API (API for Testing)

https://reqres.in/

Provides endpoints for:

- GET requests
- POST requests
- authentication simulation

Used frequently for API learning and testing.

## 📌 Suggested Learning Flow

1. Start with Red Hat’s explanation of APIs.
2. Study REST architecture using restfulapi.net.
3. Learn API design best practices from Microsoft documentation.
4. Explore OpenAPI / Swagger documentation.
5. Test APIs using Postman or Hoppscotch.
6. Practice using Fake Store API or JSONPlaceholder APIs.

> Modern software systems are built around APIs. Understanding API design and usage is essential for building scalable distributed systems.
