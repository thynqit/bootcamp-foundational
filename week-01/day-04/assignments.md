# Assignments – Day 4: User Stories & Project Tracking

> Part of the Thynqit Labs – Foundational Engineering Bootcamp

---

## 📌 Overview

Apply structured requirement writing and issue tracking using a realistic product development simulation.

These exercises help you practice:

- writing effective user stories
- defining acceptance criteria
- organizing work in an issue tracking system
- simulating Agile sprint workflows

---

## 🧠 Conceptual Questions

Answer briefly in your own words:

1. What makes a good user story?
2. Why must user stories focus on user value instead of implementation?
3. What is the purpose of acceptance criteria?
4. What is the difference between an Epic and a Story?
5. Why is backlog refinement important before sprint planning?

---

## ✍️ Practical Exercise – Writing User Stories (Without Tool)

You are building an **E-commerce Platform**.

Write user stories for the following features using the standard format:

> As a [user], I want [goal], so that [benefit].

### Features

1. User Registration
2. User Login
3. Browse Products
4. Add to Cart
5. Checkout with Payment
6. View Order History

For **at least 3 stories**, write detailed acceptance criteria.

Example format:

Acceptance Criteria:

- Given ...
- When ...
- Then ...

---

## 🛠 Practical Exercise – Real Jira Hands-On

Now implement your stories using a real issue tracking system.

---

### Step 1 – Create a Free Jira Account

1. Visit: https://www.atlassian.com/software/jira  
2. Click **Get it free**  
3. Create a free Jira Software Cloud account  
4. Create a new **Scrum project**

---

### Step 2 – Create Project Structure

Project Name:

> E-Commerce Platform

Inside the project:

- Create **1 Epic**: `Core Shopping Experience`
- Create **at least 6 User Stories** under this Epic
- Add **acceptance criteria** to each story
- Assign **story points** (Small / Medium / Large or Fibonacci scale)

---

### Step 3 – Create a Sprint

1. Go to **Backlog**
2. Create a new **Sprint**
3. Add **4–5 stories** to Sprint 1
4. Define a **Sprint Goal**
5. Start the Sprint

---

### Step 4 – Simulate Workflow

Move stories through workflow:

**To Do → In Progress → Done**

Add comments to at least **2 stories** simulating:

- clarification discussion
- QA feedback

---

## 🧩 Scenario-Based Thinking – Identify Quality Issues

Review your created stories and answer:

1. Are any stories too large?
2. Are acceptance criteria measurable?
3. Is any story too technical?
4. Did you define user value clearly?

Refactor **at least one story** to improve clarity.

---

## 🗂 Practical Thinking – Backlog Prioritization

Reorder your backlog based on:

- business value
- risk
- dependencies

Explain:

- Why did you choose this order?
- Which feature should be delivered first and why?

---

## 🔄 Reflection

Answer briefly:

1. How did using Jira change your understanding of Agile?
2. What challenges did you face while writing stories?
3. Why is visibility important in team-based software development?
4. How does structured tracking reduce project risk?
